## 1. `Loader.jsx` — drei progress UI

```jsx
import { Html, useProgress } from "@react-three/drei";

const Loader = () => {
  const { progress } = useProgress();
  return (
    <Html center className="text-xl font-normal text-center">
      {progress}% Loaded
    </Html>
  );
};

export default Loader;
```

- `useProgress()` from drei aggregates loading state of all `useGLTF`/`useTexture` calls happening inside the current `<Suspense>` boundary.
- `<Html center>` renders DOM (regular HTML) inside the 3D canvas, centered. drei creates a CSS3D-style overlay so the text floats in front of the scene.

Used as `<Suspense fallback={<Loader />}>` around the Astronaut.

## 2. `Astronaut.jsx` — glTF model with animations

Auto-generated by [`gltfjsx`](https://github.com/pmndrs/gltfjsx) (you can see the comment at top). The interesting hand-written part:

```jsx
import { useGLTF, useAnimations } from "@react-three/drei";
import { useMotionValue, useSpring } from "motion/react";
import { useFrame } from "@react-three/fiber";

export function Astronaut(props) {
  const group = useRef();
  const { nodes, materials, animations } = useGLTF(
    "/models/tenhun_falling_spaceman_fanart.glb"
  );
  const { actions } = useAnimations(animations, group);
  useEffect(() => {
    if (animations.length > 0) {
      actions[animations[0].name]?.play();
    }
  }, [actions, animations]);

  const yPosition = useMotionValue(5);
  const ySpring = useSpring(yPosition, { damping: 30 });
  useEffect(() => {
    ySpring.set(-1);
  }, [ySpring]);

  useFrame(() => {
    group.current.position.y = ySpring.get();
  });

  return (
    <group ref={group} {...props} dispose={null}
           rotation={[-Math.PI / 2, -0.2, 2.2]}
           scale={props.scale || 0.3}
           position={props.position || [1.3, -1, 0]}>
      <group name="Sketchfab_Scene"> ... </group>
    </group>
  );
}

useGLTF.preload("/models/tenhun_falling_spaceman_fanart.glb");
```

### Line-by-line

- `useGLTF("/path.glb")` — loads a binary glTF. Returns `{ nodes, materials, animations, scene }`. **Suspends** until the file is loaded — that's why this must be inside `<Suspense>`.
- `useAnimations(animations, group)` — wires up the model's baked animations to play against the group ref.
- `actions[animations[0].name]?.play()` — plays the first animation by name. `?.` (optional chaining) guards against undefined.
- **The fall-in trick**:
  - `useMotionValue(5)` — start at y = 5 (above scene).
  - `useSpring(yPosition, { damping: 30 })` — springs toward whatever `yPosition` holds.
  - On mount, `ySpring.set(-1)` changes the target to -1. The spring smoothly animates from 5 → -1.
  - `useFrame(() => group.current.position.y = ySpring.get())` — every frame, copy the current spring value into the Three group. **MotionValues don't trigger React renders** — they update DOM/Three directly, which is exactly what we want for 60fps animation.
- `useGLTF.preload(...)` (outside the component) — starts the network request at module load, so by the time the component mounts the model is often already cached.

### Why `dispose={null}`?

When R3F unmounts a `<mesh>`/`<group>`, it calls `dispose()` on geometries and materials by default. For shared resources from `useGLTF` (which other instances may also use), you set `dispose={null}` to keep them alive.

## 3. `Globe.jsx` — interactive draggable globe

Uses the [`cobe`](https://github.com/shuding/cobe) library (a tiny WebGL globe renderer) wrapped in React state for drag-to-rotate.

```jsx
import createGlobe from "cobe";
import { useMotionValue, useSpring } from "motion/react";

export function Globe({ className, config = GLOBE_CONFIG }) {
  const phiRef = useRef(0);
  const canvasRef = useRef(null);
  const pointerInteracting = useRef(null);
  const r = useMotionValue(0);
  const rs = useSpring(r, { mass: 1, damping: 30, stiffness: 100 });

  const updatePointerInteraction = (value) => {
    pointerInteracting.current = value;
    canvasRef.current.style.cursor = value !== null ? "grabbing" : "grab";
  };

  const updateMovement = (clientX) => {
    if (pointerInteracting.current !== null) {
      const delta = clientX - pointerInteracting.current;
      r.set(r.get() + delta / MOVEMENT_DAMPING);
    }
  };

  useEffect(() => {
    const globe = createGlobe(canvasRef.current, {
      ...config,
      onRender: (state) => {
        if (!pointerInteracting.current) phiRef.current += 0.005;
        state.phi = phiRef.current + rs.get();
      },
    });
    return () => globe.destroy();
  }, [rs, config]);

  return (
    <canvas
      ref={canvasRef}
      onPointerDown={(e) => {
        pointerInteracting.current = e.clientX;
        updatePointerInteraction(e.clientX);
      }}
      onPointerUp={() => updatePointerInteraction(null)}
      onPointerOut={() => updatePointerInteraction(null)}
      onMouseMove={(e) => updateMovement(e.clientX)}
      onTouchMove={(e) => e.touches[0] && updateMovement(e.touches[0].clientX)}
    />
  );
}
```

### Key ideas

- **All ref-based, no state** in the hot path. `useRef` is used for `phiRef`, `pointerInteracting`, `canvasRef` — none of these need a re-render when they change.
- **`MotionValue` + `useSpring`** for drag rotation:
  - `r` is the user's drag input. When you drag, `r.set(r.get() + delta/1400)` adds rotation.
  - `rs` is the smoothed (spring) version. The globe reads `rs.get()` each frame.
- **`onRender(state)`** is a `cobe` hook that runs every frame. We mutate `state.phi` (longitude) to either auto-spin (`+= 0.005` when idle) or follow user drag.
- `createGlobe(canvas, config)` returns an instance with `.destroy()`. We call destroy on unmount.

### Performance note

Notice we never call `setState` during interaction — no React re-render. This is the **right** way to do a high-fps interactive widget.

## 4. `Particles.jsx` — canvas-based particle field that reacts to mouse

A custom canvas particle system, framework-free except for thin React state for the mouse position.

```jsx
function MousePosition() {
  const [mousePosition, setMousePosition] = useState({ x: 0, y: 0 });
  useEffect(() => {
    const handleMouseMove = (event) => {
      setMousePosition({ x: event.clientX, y: event.clientY });
    };
    window.addEventListener("mousemove", handleMouseMove);
    return () => window.removeEventListener("mousemove", handleMouseMove);
  }, []);
  return mousePosition;
}
```

A custom hook (despite not starting with `use`) that returns the current mouse position. **This is wasteful** — every mousemove triggers a re-render. The cleaner pattern is to write to a `useRef` and let the canvas loop read from it. (Stick a `useRef` here in your version.)

```jsx
function hexToRgb(hex) {
  hex = hex.replace("#", "");
  if (hex.length === 3) hex = hex.split("").map(c => c + c).join("");
  const hexInt = parseInt(hex, 16);
  return [(hexInt >> 16) & 255, (hexInt >> 8) & 255, hexInt & 255];
}
```

Standard hex→RGB conversion. Uses bit shifts: `hexInt >> 16` shifts the red byte to the low byte, `& 255` masks to keep just that byte.

```jsx
const circleParams = () => {
  const x = Math.floor(Math.random() * canvasSize.current.w);
  const y = Math.floor(Math.random() * canvasSize.current.h);
  const pSize = Math.floor(Math.random() * 2) + size;
  const targetAlpha = parseFloat((Math.random() * 0.6 + 0.1).toFixed(1));
  const dx = (Math.random() - 0.5) * 0.1;
  const dy = (Math.random() - 0.5) * 0.1;
  const magnetism = 0.1 + Math.random() * 4;
  return { x, y, translateX: 0, translateY: 0, size: pSize, alpha: 0, targetAlpha, dx, dy, magnetism };
};
```

Each particle is a plain object:
- `x, y` — current pixel position.
- `translateX, translateY` — offset added each frame (lets us animate them without modifying x/y).
- `size` — radius in px.
- `alpha` — current opacity (animates up to `targetAlpha`).
- `dx, dy` — random per-frame drift.
- `magnetism` — how strongly the particle reacts to mouse proximity.

```jsx
const drawCircle = (circle, update = false) => {
  context.current.translate(translateX, translateY);
  context.current.beginPath();
  context.current.arc(x, y, size, 0, 2 * Math.PI);
  context.current.fillStyle = `rgba(${rgb.join(", ")}, ${alpha})`;
  context.current.fill();
  context.current.setTransform(dpr, 0, 0, dpr, 0, 0);
  if (!update) circles.current.push(circle);
};
```

- `context.current.translate(tx, ty)` — translates the canvas drawing matrix.
- `beginPath() + arc(...) + fill()` — draw a circle.
- `setTransform(dpr, 0, 0, dpr, 0, 0)` — **reset** the matrix back to dpr scale. Without this reset, every `translate` accumulates and you get a runaway transform.

The full animate loop (later in the file) calls `requestAnimationFrame(animate)` and:
1. Clears the canvas.
2. Updates each particle's position, alpha, drift.
3. Computes distance to mouse → moves particle toward/away.
4. Re-draws.

**This is the textbook canvas particle pattern.** Adapt it for any canvas effect you want.

## 5. `FlipWords.jsx` — cycling word animation with per-letter staggered reveal

```jsx
export const FlipWords = ({ words, duration = 3000, className }) => {
  const [currentWord, setCurrentWord] = useState(words[0]);
  const [isAnimating, setIsAnimating] = useState(false);

  const startAnimation = useCallback(() => {
    const word = words[words.indexOf(currentWord) + 1] || words[0];
    setCurrentWord(word);
    setIsAnimating(true);
  }, [currentWord, words]);

  useEffect(() => {
    if (!isAnimating)
      setTimeout(() => { startAnimation(); }, duration);
  }, [isAnimating, duration, startAnimation]);

  return (
    <AnimatePresence onExitComplete={() => setIsAnimating(false)}>
      <motion.div
        initial={{ opacity: 0, y: 10 }}
        animate={{ opacity: 1, y: 0 }}
        exit={{ opacity: 0, y: -40, x: 40, filter: "blur(8px)", scale: 2, position: "absolute" }}
        transition={{ type: "spring", stiffness: 100, damping: 10 }}
        key={currentWord}
      >
        {currentWord.split(" ").map((word, wordIndex) => (
          <motion.span key={word + wordIndex} ...>
            {word.split("").map((letter, letterIndex) => (
              <motion.span
                key={word + letterIndex}
                initial={{ opacity: 0, y: 10, filter: "blur(8px)" }}
                animate={{ opacity: 1, y: 0, filter: "blur(0px)" }}
                transition={{ delay: wordIndex * 0.3 + letterIndex * 0.05, duration: 0.2 }}
              >
                {letter}
              </motion.span>
            ))}
            <span>&nbsp;</span>
          </motion.span>
        ))}
      </motion.div>
    </AnimatePresence>
  );
};
```

### How it works

- **State**: `currentWord` (the word being shown), `isAnimating` (whether a transition is in progress).
- **`startAnimation()`**:
  - Find next word: `words[words.indexOf(currentWord) + 1] || words[0]` (wraps to start at end).
  - Set it, mark animating.
- **`useEffect(..., [isAnimating, duration, startAnimation])`**: when not animating, schedule the next word swap after `duration` ms. The dep array includes `startAnimation` because of the linter rule — that's why `useCallback` wraps it.
- **`AnimatePresence`** (Framer Motion):
  - Required for **exit animations** to play. Without it, removing an element from the tree is instant.
  - `onExitComplete` fires after the exit animation finishes → set `isAnimating(false)` → effect schedules next word.
- **`key={currentWord}`**: when the word changes, the key changes → Framer treats it as "old element exit, new element enter" → exit + initial animations fire.
- **Per-letter stagger**: `delay: wordIndex * 0.3 + letterIndex * 0.05` — each letter delayed by its position. Cascade effect.

## 6. `Card.jsx` — draggable label

```jsx
const Card = ({ style, text, image, containerRef }) => {
  return image && !text ? (
    <motion.img className="absolute w-15 cursor-grab" src={image} style={style}
      whileHover={{ scale: 1.05 }}
      drag dragConstraints={containerRef} dragElastic={1} />
  ) : (
    <motion.div className="absolute ... bg-storm w-[12rem] cursor-grab" style={style}
      whileHover={{ scale: 1.05 }}
      drag dragConstraints={containerRef} dragElastic={1}>
      {text}
    </motion.div>
  );
};
```

### Framer Motion drag

- `drag` (boolean) → enables dragging on both axes. `drag="x"` or `drag="y"` for single axis.
- `dragConstraints={containerRef}` → can't be dragged outside `containerRef`'s bounding box. (You can also pass `{ top, left, right, bottom }`.)
- `dragElastic={1}` → "rubber band" resistance. `0` = hard stop at boundary, `1` = unrestricted but snaps back.
- `whileHover={{ scale: 1.05 }}` → temporary state while hovered.

The ternary picks between `<motion.img>` (image-only) and `<motion.div>` (text). Note that `<motion.img>` won't render the `text`, even if both are provided — slight asymmetry to be aware of.

## 7. `OrbitingCircles.jsx` — orbit animation with CSS custom properties

```jsx
export function OrbitingCircles({ children, reverse, duration = 20, radius = 160, path = true, iconSize = 30, speed = 1, ...props }) {
  const calculatedDuration = duration / speed;
  return (
    <>
      {path && (
        <svg className="pointer-events-none absolute inset-0 size-full">
          <circle cx="50%" cy="50%" r={radius} fill="none" />
        </svg>
      )}
      {React.Children.map(children, (child, index) => {
        const angle = (360 / React.Children.count(children)) * index;
        return (
          <div
            style={{
              "--duration": calculatedDuration,
              "--radius": radius,
              "--angle": angle,
              "--icon-size": `${iconSize}px`,
            }}
            className="absolute flex size-[var(--icon-size)] transform-gpu animate-orbit items-center justify-center rounded-full"
          >
            {child}
          </div>
        );
      })}
    </>
  );
}
```

### The orbit keyframe (defined in `index.css`)

```css
@keyframes orbit {
  0% {
    transform: rotate(calc(var(--angle) * 1deg))
               translateY(calc(var(--radius) * 1px))
               rotate(calc(var(--angle) * -1deg));
  }
  100% {
    transform: rotate(calc(var(--angle) * 1deg + 360deg))
               translateY(calc(var(--radius) * 1px))
               rotate(calc((var(--angle) * -1deg) - 360deg));
  }
}
```

### How the trigonometry works

- `rotate(angle)` then `translateY(radius)` = moves the element to a point on a circle of `radius`, at the given `angle` from the center.
- The trailing inverse `rotate(-angle)` keeps the icon **upright** even though the parent rotation would tip it.
- From 0% to 100% we add `+360deg` and `-360deg` so the icon orbits the center while staying upright.

### `React.Children.map`

- `React.Children.map(children, fn)` is the safe way to iterate `children` (handles single-child, null, and array cases).
- `React.Children.count(children)` gives the count — used to compute equal angular spacing.

### CSS custom properties as React style

- `style={{ "--duration": 20, "--radius": 160, "--angle": 45 }}` — yes, custom properties (CSS variables) work in inline style objects.
- The animation utility class `animate-orbit` is generated by Tailwind from `--animate-orbit: orbit 50s linear infinite;` defined in `@theme`.

This is **the** pattern for "orbit around a point" — useful for tech-stack carousels, loading spinners, etc.

## What this folder teaches you

- **3D model loading** via `useGLTF` + `useAnimations`.
- **Canvas-based particle systems** with `requestAnimationFrame` and pixel-ratio awareness (`dpr`).
- **MotionValues** for high-fps interaction without React re-renders.
- **AnimatePresence** + `key` swap for exit/enter animations.
- **CSS custom properties as React inline style** for parameterized keyframes (the orbit trick).
- **React.Children API** for iterating children safely.
