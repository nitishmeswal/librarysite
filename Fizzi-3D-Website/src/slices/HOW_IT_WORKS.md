# Fizzi-3D-Website / src/slices — How It Works

Each subfolder is a Prismic **slice** (a reusable content block placed in the CMS). Folder layout:

```
slices/
├── Hero/
│   ├── index.tsx           # React component
│   ├── Scene.tsx           # R3F scene (the 3D content)
│   ├── Bubbles.tsx         # InstancedMesh particles
│   ├── mocks.json          # Sample data for slice simulator
│   ├── model.json          # Prismic content type definition
│   └── screenshot-default.png
├── Carousel/
│   ├── index.tsx           # Flavor carousel
│   ├── ArrowIcon.tsx       # SVG
│   ├── WavyCircles.tsx     # SVG background
│   └── model.json + mocks.json + screenshot
├── SkyDive/
│   ├── index.tsx
│   ├── Scene.tsx           # 3D sky-dive scene with clouds + 3D text
│   └── model.json + ...
├── AlternatingText/
│   ├── index.tsx
│   ├── Scene.tsx
│   └── model.json + ...
├── BigText/
│   ├── index.tsx           # Pure CSS, no 3D
│   └── model.json + ...
└── index.ts                # Exports `components` map
```

## The slice pattern

Each `index.tsx` exports a component that receives a typed `slice` prop from Prismic:

```tsx
export type HeroProps = SliceComponentProps<Content.HeroSlice>;

const Hero = ({ slice }: HeroProps): JSX.Element => {
  // slice.primary.heading, slice.primary.subheading, etc.
  return <section>...</section>;
};
```

The `Content.HeroSlice` type is auto-generated by Prismic's TypeScript codegen from `prismicio-types.d.ts`.

### `mocks.json` and `model.json`

- `model.json` — Prismic content-type schema. Defines fields like `heading: TitleField`, `body: RichTextField`, `cans_image: ImageField`. Editors edit this content in Prismic.
- `mocks.json` — sample data for local development. The Slice Simulator (Next.js route at `/slice-simulator`) uses this to preview slices without hitting Prismic.

## 1. Hero slice — `slices/Hero/index.tsx`

The opening of the page. Five 3D cans floating around, text reveals on load, scroll-triggered scene rotations.

### Entry timeline

```tsx
const ready = useStore((state) => state.ready);
const isDesktop = useMediaQuery("(min-width: 768px)", true);

useGSAP(
  () => {
    if (!ready && isDesktop) return;

    const introTl = gsap.timeline();

    introTl
      .set(".hero", { opacity: 1 })
      .from(".hero-header-word", {
        scale: 3, opacity: 0, ease: "power4.in", delay: 0.3, stagger: 1,
      })
      .from(".hero-subheading", { opacity: 0, y: 30 }, "+=.8")
      .from(".hero-body", { opacity: 0, y: 10 })
      .from(".hero-button", { opacity: 0, y: 10, duration: 0.6 });

    // ...
  },
  { dependencies: [ready, isDesktop] },
);
```

### `if (!ready && isDesktop) return`

Don't run animations on desktop until 3D scene is ready (per the Zustand store).

On mobile, `isDesktop = false`, so `(!ready && false) = false` → condition is false → run anyway. Mobile users see the animation immediately (since they don't get the 3D scene at all due to `hidden md:block`).

### The 3-times-scale word reveal

```tsx
.from(".hero-header-word", { scale: 3, opacity: 0, ease: "power4.in", stagger: 1 })
```

Words start at `scale: 3` (huge, overflowing) and animate down to `scale: 1` (final size) while fading in. `power4.in` ease = slow start, fast finish → dramatic punch. Stagger of `1` = 1 second between words → words appear like "BOOM... BOOM... BOOM".

### `"+=0.8"` position parameter

```tsx
.from(".hero-subheading", { opacity: 0, y: 30 }, "+=.8")
```

Start this tween 0.8s AFTER the previous one ends. (`-=` would mean BEFORE.)

### The scroll timeline — body color change

```tsx
const scrollTl = gsap.timeline({
  scrollTrigger: { trigger: ".hero", start: "top top", end: "bottom bottom", scrub: 1.5 },
});

scrollTl
  .fromTo("body",
    { backgroundColor: "#FDE047" },
    { backgroundColor: "#D9F99D", overwrite: "auto" },
    1,
  )
  .from(".text-side-heading .split-char", {
    scale: 1.3, y: 40, rotate: -25, opacity: 0,
    stagger: 0.1, ease: "back.out(3)", duration: 0.5,
  })
  .from(".text-side-body", { y: 20, opacity: 0 });
```

### `overwrite: "auto"`

Without this, if another tween is also targeting `body { backgroundColor }`, both fight for the same property → unpredictable behavior. `overwrite: "auto"` tells GSAP "kill any other tweens on this property when this one starts". Safer.

### `back.out(3)` ease

`back.out(N)` is an "overshoot" easing — animation goes past target, then settles back. `N` is the overshoot amount. `back.out(3)` is dramatic overshoot — feels playful.

### The 3D scene placement

```tsx
{isDesktop && (
  <View className="hero-scene pointer-events-none sticky top-0 z-50 -mt-[100vh] hidden h-screen w-screen md:block">
    <Scene />
    <Bubbles count={300} speed={2} repeat={true} />
  </View>
)}
```

- **`isDesktop && ...`** — only render on desktop. The hook is SSR-safe so this works correctly.
- **`sticky top-0`** — keeps the 3D scene visible while user scrolls within the hero.
- **`-mt-[100vh]`** — pulls the View up so it overlaps the previous content (covers the full screen as user scrolls into the hero).
- **`pointer-events-none`** — clicks pass through to the underlying DOM (text, buttons).
- **`z-50`** — above most page content but below modals.

## 2. Hero slice — `slices/Hero/Scene.tsx`

This is the Three.js scene rendered inside the Hero's `<View>`.

### Refs for all five cans + parent group

```tsx
const can1Ref = useRef<Group>(null);  // ...up to can5Ref
const can1GroupRef = useRef<Group>(null);
const can2GroupRef = useRef<Group>(null);
const groupRef = useRef<Group>(null);
```

### Why a wrapper group?

```tsx
<group ref={groupRef}>
  <group ref={can1GroupRef}>
    <FloatingCan ref={can1Ref} flavor="blackCherry" />
  </group>
  <group ref={can2GroupRef}>
    <FloatingCan ref={can2Ref} flavor="lemonLime" />
  </group>
  <FloatingCan ref={can3Ref} flavor="grape" />
  ...
</group>
```

Two **layers of grouping** allow independent animations:
- `groupRef` rotates the **entire scene** as you scroll.
- `can1GroupRef` animates the **intro** position/rotation for cans 1 and 2.
- `can1Ref` lets you animate the **resting position** of can 1 independently.

It's the same pattern as nested CSS containers — each level animates a different axis.

### Initial positions

```tsx
gsap.set(can1Ref.current.position, { x: -1.5 });
gsap.set(can1Ref.current.rotation, { z: -0.5 });

gsap.set(can2Ref.current.position, { x: 1.5 });
gsap.set(can2Ref.current.rotation, { z: 0.5 });

gsap.set(can3Ref.current.position, { y: 5, z: 2 });
gsap.set(can4Ref.current.position, { x: 2, y: 4, z: 2 });
gsap.set(can5Ref.current.position, { y: -5 });
```

`gsap.set` writes properties immediately (no animation). Used to set the starting layout of all cans.

### The intro animation (only if `window.scrollY < 20`)

```tsx
if (window.scrollY < 20) {
  introTl
    .from(can1GroupRef.current.position, { y: -5, x: 1 }, 0)
    .from(can1GroupRef.current.rotation, { z: 3 }, 0)
    .from(can2GroupRef.current.position, { y: 5, x: 1 }, 0)
    .from(can2GroupRef.current.rotation, { z: 3 }, 0);
}
```

If the user is at the top of the page, run the intro: cans 1 and 2 "fly in" from above/below + rotate.

If user is mid-scroll (refresh while scrolled), skip the intro — the cans are already in their resting positions.

### Scroll-driven scene rotation

```tsx
const scrollTl = gsap.timeline({
  scrollTrigger: { trigger: ".hero", start: "top top", end: "bottom bottom", scrub: 1.5 },
});

scrollTl
  .to(groupRef.current.rotation, { y: Math.PI * 2 })  // full 360° rotation of entire scene
  .to(can1Ref.current.position, { x: -0.2, y: -0.7, z: -2 }, 0)
  .to(can1Ref.current.rotation, { z: 0.3 }, 0)
  // ... cans 2-5 similar ...
  .to(groupRef.current.position, { x: 1, duration: 3, ease: "sine.inOut" }, 1.3);
```

As user scrolls:
- Entire scene rotates 360° on Y axis.
- Each can moves to a different position.
- All happen simultaneously (`, 0` position param).

`Math.PI * 2` = 360° in radians (Three.js uses radians).

### `<Environment>` for HDR lighting

```tsx
<Environment files="/hdr/lobby.hdr" environmentIntensity={1.5} />
```

`<Environment>` (drei) loads an HDR image and uses it as the environment lighting for all PBR (physically-based rendering) materials in the scene. Without this, materials look flat. With it, metal cans reflect realistic lighting.

HDR files (.hdr) are 32-bit float per channel images used for image-based lighting (IBL).

## 3. Carousel slice — `slices/Carousel/index.tsx`

A clickable flavor carousel. Each click rotates the can N times + changes label + changes background color.

### State for current flavor

```tsx
const [currentFlavorIndex, setCurrentFlavorIndex] = useState(0);
const sodaCanRef = useRef<Group>(null);
```

### The change-flavor animation

```tsx
function changeFlavor(index: number) {
  if (!sodaCanRef.current) return;

  const nextIndex = (index + FLAVORS.length) % FLAVORS.length;

  const tl = gsap.timeline();

  tl.to(sodaCanRef.current.rotation, {
    y: index > currentFlavorIndex
      ? `-=${Math.PI * 2 * SPINS_ON_CHANGE}`
      : `+=${Math.PI * 2 * SPINS_ON_CHANGE}`,
    ease: "power2.inOut",
    duration: 1,
  }, 0)
    .to(".background, .wavy-circles-outer, .wavy-circles-inner", {
      backgroundColor: FLAVORS[nextIndex].color,
      fill: FLAVORS[nextIndex].color,
      ease: "power2.inOut",
      duration: 1,
    }, 0)
    .to(".text-wrapper", { duration: 0.2, y: -10, opacity: 0 }, 0)
    .to({}, { onStart: () => setCurrentFlavorIndex(nextIndex) }, 0.5)
    .to(".text-wrapper", { duration: 0.2, y: 0, opacity: 1 }, 0.7);
}
```

### `Math.PI * 2 * SPINS_ON_CHANGE`

`SPINS_ON_CHANGE = 8` → 8 full rotations every time you click. The can spins dramatically.

### Relative rotation: `"-=" + value` vs `"+=" + value`

```tsx
y: index > currentFlavorIndex ? `-=${...}` : `+=${...}`
```

If moving forward, rotate clockwise. If moving backward, rotate counter-clockwise. Direction matches the conceptual motion.

GSAP accepts relative values: `"+=5"`, `"-=5"`, `"*=2"`, `"/=2"`. The string starts with operator + value.

### Tweening with `{}` and `onStart`

```tsx
.to({}, { onStart: () => setCurrentFlavorIndex(nextIndex) }, 0.5)
```

You can tween an empty object `{}` just to schedule a callback at a specific timeline position. At 0.5s into the timeline, `setCurrentFlavorIndex(nextIndex)` fires → React re-renders with the new flavor + label.

The visual sequence:
1. (t=0) Start spinning + fading text out + changing background.
2. (t=0.5) Mid-spin, swap the React state → new flavor texture renders (because `<FloatingCan flavor={FLAVORS[currentFlavorIndex].flavor}>`).
3. (t=0.7) Fade new flavor name back in.

By the time the can stops spinning, you see the new flavor. **Perfectly disguised state swap**.

### Multi-selector animation

```tsx
".background, .wavy-circles-outer, .wavy-circles-inner"
```

Three different elements animated together to the same color. Cohesive theming change.

### `<Center>` from drei

```tsx
<View className="aspect-square h-[70vmin] min-h-40">
  <Center position={[0, 0, 1.5]}>
    <FloatingCan ref={sodaCanRef} ... />
  </Center>
  ...
</View>
```

`<Center>` automatically centers its children's bounding box at the origin. Useful when you don't know exact dimensions of an imported model — let drei figure it out.

### Modulo for wrap

```tsx
const nextIndex = (index + FLAVORS.length) % FLAVORS.length;
```

Same trick from Mojito slider — handles negative `index` correctly.

## 4. SkyDive slice — `slices/SkyDive/Scene.tsx`

The most cinematic slice. A can falls from sky through clouds, with 3D text words rising past it.

### The 75° angle

```tsx
const ANGLE = 75 * (Math.PI / 180);

const getXPosition = (distance: number) => distance * Math.cos(ANGLE);
const getYPosition = (distance: number) => distance * Math.sin(ANGLE);
```

A 75° trajectory through the screen — like the can is falling diagonally from upper-right. `cos(75°) ≈ 0.26`, `sin(75°) ≈ 0.97` → motion is mostly vertical with a slight horizontal drift.

`Math.PI / 180` converts degrees to radians (since `Math.cos/sin` take radians).

### Infinite cloud movement

```tsx
gsap.to(cloud1Ref.current.position, {
  y: `+=${getYPosition(DISTANCE * 2)}`,
  x: `+=${getXPosition(DISTANCE * -2)}`,
  ease: "none",
  repeat: -1,
  duration: DURATION,
});

gsap.to(cloud2Ref.current.position, {
  y: `+=${getYPosition(DISTANCE * 2)}`,
  x: `+=${getXPosition(DISTANCE * -2)}`,
  ease: "none",
  repeat: -1,
  delay: DURATION / 2,  // offset by half the duration → continuous flow
  duration: DURATION,
});
```

Two clouds. Each moves diagonally. Second one is delayed by half the duration → as one finishes its loop, the other is mid-way → continuous motion.

`repeat: -1` = infinite repeat.

### Spinning can — endless rotation

```tsx
gsap.to(canRef.current.rotation, {
  y: Math.PI * 2,
  duration: 1.7,
  repeat: -1,
  ease: "none",
});
```

Rotates 360° forever, no easing.

### Word positions via map

```tsx
gsap.set(
  wordsRef.current.children.map((word) => word.position),
  { ...getXYPositions(7), z: 2 },
);
```

`wordsRef.current.children` is an array of all Three.js groups inside the words ref. Map to their `position` properties. Set all of them at once.

GSAP accepts arrays of targets — applies the same props to each.

### Keyframes inside a tween

```tsx
.to(
  wordsRef.current.children.map((word) => word.position),
  {
    keyframes: [
      { x: 0, y: 0, z: -1 },
      { ...getXYPositions(-7), z: -7 },
    ],
    stagger: 0.3,
  },
  0,
);
```

`keyframes` in GSAP = "go through these intermediate states in order". Each keyframe is a snapshot of property values. GSAP interpolates between them.

So each word moves: initial position → (0, 0, -1) → far away offscreen.

### `<Clouds>` + `<Cloud>` (drei)

```tsx
<Clouds ref={cloudsRef}>
  <Cloud ref={cloud1Ref} bounds={[10, 10, 2]} />
  <Cloud ref={cloud2Ref} bounds={[10, 10, 2]} />
</Clouds>
```

drei has built-in volumetric cloud rendering. `<Clouds>` is the parent; `<Cloud>` is a single cloud volume. `bounds` defines the cloud's bounding box.

Behind the scenes: a billboarded shader that simulates volumetric cloud density. Looks beautiful, costs cheap.

### 3D Text rendering

```tsx
function ThreeText({ sentence, color }) {
  const words = sentence.toUpperCase().split(" ");
  const material = new THREE.MeshLambertMaterial();
  const isDesktop = useMediaQuery("(min-width: 950px)", true);

  return words.map((word, wordIndex) => (
    <Text
      key={`${wordIndex}-${word}`}
      scale={isDesktop ? 1 : 0.5}
      color={color}
      material={material}
      font="/fonts/Alpino-Variable.woff"
      fontWeight={900}
      anchorX={"center"}
      anchorY={"middle"}
      characters="ABCDEFGHIJKLMNOPQRSTUVWXYZ!,.?'"
    >
      {word}
    </Text>
  ));
}
```

drei's `<Text>` renders SDF (signed distance field) text in 3D. Each word becomes a separate 3D object.

- `font="/fonts/...woff"` — the font file (must be served from public/).
- `fontWeight={900}` — uses the right weight from the variable font.
- `anchorX="center"` + `anchorY="middle"` — text origin at center (so position is at center, not top-left).
- `characters="..."` — pre-rasterize ONLY these characters (smaller atlas, faster init).

## 5. AlternatingText slice — `slices/AlternatingText/index.tsx`

Alternating left/right text blocks with a shared 3D scene in the background.

```tsx
{slice.primary.text_group.map((item, index) => (
  <div
    key={asText(item.heading)}
    className="alternating-section grid h-screen place-items-center gap-x-12 md:grid-cols-2"
  >
    <div
      className={clsx(
        index % 2 === 0 ? "col-start-1" : "md:col-start-2",
        "rounded-lg p-4 backdrop-blur-lg max-md:bg-white/30",
      )}
    >
      <h2 className="text-balance text-6xl font-bold">
        <PrismicText field={item.heading} />
      </h2>
      <div className="mt-4 text-xl">
        <PrismicRichText field={item.body} />
      </div>
    </div>
  </div>
))}
```

### `index % 2 === 0 ? "col-start-1" : "md:col-start-2"`

Even-indexed items go left, odd go right. CSS grid `col-start-1` vs `col-start-2`.

### `text-balance`

CSS property `text-wrap: balance` — distributes text into more visually balanced lines. New CSS feature; Tailwind has a utility.

### `backdrop-blur-lg`

CSS `backdrop-filter: blur(...)`. Frosted-glass look behind the text card. Combined with `max-md:bg-white/30` (only on mobile), text remains readable.

### `<PrismicText>` vs `<PrismicRichText>`

- `<PrismicText>` — renders the plain text of a Prismic Title field.
- `<PrismicRichText>` — renders rich text (bold, italics, links, lists). Use this for body content.
- `asText(field)` — extracts plain text from any Prismic field (for keys, meta, etc.).

## 6. BigText slice — `slices/BigText/index.tsx`

Pure CSS, no 3D. Massive typography that fills the viewport.

```tsx
<section className="min-h-screen w-screen overflow-hidden bg-[#FE6334] text-[#FEE832]">
  <h2 className="grid w-full gap-[3vw] py-10 text-center font-black uppercase leading-[.7]">
    <div className="text-[34vw]">Soda</div>
    <div className="grid gap-[3vw] text-[34vw] md:flex md:text-[11vw]">
      <span className="inline-block">that </span>
      <span className="inline-block max-md:text-[27vw]">makes </span>
      <span className="inline-block max-md:text-[40vw]">you </span>
    </div>
    <div className="text-[32vw]">Smile</div>
  </h2>
</section>
```

### `text-[34vw]` — viewport-width sized text

`text-[34vw]` = `font-size: 34vw`. 34% of viewport width. Massive responsive typography.

### `leading-[.7]`

`line-height: 0.7`. Tight line spacing for big display headings (default is 1.5, way too loose for huge text).

### `max-md:text-[27vw]`

Tailwind's `max-md:` prefix = "applies UP TO md breakpoint" (the opposite of `md:`). Used here to adjust mobile sizing.

### Why no animation here?

This slice is meant to be a "breather" — pure visual impact, no motion. Sometimes the best slice is one that doesn't move.

### Build a click-to-change-flavor 3D carousel (20 minutes)

```tsx
function FlavorCarousel({ flavors }) {
  const [index, setIndex] = useState(0);
  const ref = useRef<Group>(null);

  const change = (newIndex: number) => {
    const nextIndex = (newIndex + flavors.length) % flavors.length;
    const tl = gsap.timeline();
    tl.to(ref.current!.rotation, { y: `+=${Math.PI * 2 * 4}`, duration: 1 }, 0);
    tl.to({}, { onStart: () => setIndex(nextIndex) }, 0.5);
  };

  return (
    <>
      <button onClick={() => change(index - 1)}>Prev</button>
      <View><FloatingCan ref={ref} flavor={flavors[index]} /></View>
      <button onClick={() => change(index + 1)}>Next</button>
    </>
  );
}
```

### Build 3D text rising past camera (20 minutes)

```tsx
import { Text } from "@react-three/drei";

function RisingText({ words }) {
  const ref = useRef<Group>(null);

  useGSAP(() => {
    gsap.to(ref.current!.children.map(c => c.position), {
      keyframes: [{ z: 0 }, { z: -10 }],
      stagger: 0.3,
      scrollTrigger: { trigger: ".section", start: "top top", end: "bottom top", scrub: true },
    });
  });

  return (
    <group ref={ref}>
      {words.map((w, i) => (
        <Text key={i} position={[0, 0, 5]}>{w}</Text>
      ))}
    </group>
  );
}
```

## What this folder teaches you

- **The slice pattern**: each section is a self-contained folder with `index.tsx` + `Scene.tsx` + Prismic mock data.
- **R3F + GSAP** integration: animate Three.js objects through their `position`, `rotation`, `scale` props via refs.
- **Two-layer grouping**: outer group for whole-scene animations, inner group for individual element animations.
- **Empty-object tweens** for callbacks at specific timeline positions.
- **Keyframes inside a tween**: walk through intermediate states.
- **3D text rendering** with drei's `<Text>` + custom fonts.
- **Volumetric clouds** with drei's `<Clouds>` + `<Cloud>`.
- **HDR environment lighting** for realistic metal reflections.
- **CSS-driven big typography** with `vw` units and `leading` adjustments.
- **Prismic content fields**: `asText`, `<PrismicText>`, `<PrismicRichText>`.
