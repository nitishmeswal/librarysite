# Fizzi-3D-Website / src/app — How It Works

Next.js 14 App Router files.

```
src/app/
├── layout.tsx           # Root layout (HTML, body, providers)
├── page.tsx             # / (home page)
├── app.css              # Global Tailwind + custom styles
├── icon.svg             # Favicon
├── [uid]/               # Dynamic route for Prismic UID pages
├── api/                 # API routes (preview, revalidate)
└── slice-simulator/     # Prismic slice simulator page (dev tool)
```

---

## 1. The App Router model

**File-based routing**. The folder structure under `app/` defines URLs:

- `app/page.tsx` → `/`
- `app/about/page.tsx` → `/about`
- `app/[uid]/page.tsx` → `/anything` (dynamic)
- `app/api/foo/route.ts` → `/api/foo`

Special filenames:

- `layout.tsx` — wraps all child segments (persists across navigation).
- `page.tsx` — the actual content at a route.
- `loading.tsx` — Suspense fallback while route is loading.
- `error.tsx` — error boundary for the route.
- `route.ts` — for API routes (export `GET`, `POST`, etc.).

## 2. `layout.tsx` — already covered in parent guide

The key things to internalize:

### Server components by default

The root `layout.tsx` does NOT have `"use client"` at the top. It's a **server component**. Server components:
- Run on the server, send HTML.
- Can be `async`.
- Can directly call databases, APIs, file system.
- Can NOT use hooks like `useState`, `useEffect`.
- Can NOT use event handlers (`onClick`, etc.).

To use client features, mark a component with `"use client"` at the top:

```tsx
"use client";

import { useState } from "react";

export default function Counter() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n+1)}>{n}</button>;
}
```

Client components are SSR'd on the server then hydrated on the client (like classic Next.js Pages Router). But server components don't hydrate — their HTML is final.

### Why this matters

- Move heavy data fetching to server components (no client bundle bloat, no waterfall).
- Use client components only for interactivity (state, effects, browser APIs).
- Smaller JS bundles → faster page loads.

### `<PrismicPreview>` outside `<body>`?

```tsx
<html>
  <body>...</body>
  <PrismicPreview repositoryName={...} />
</html>
```

`<PrismicPreview>` is technically outside `<body>`. In strict HTML, only `<head>` and `<body>` belong inside `<html>`. React's JSX allows this; the actual rendered HTML will probably put it inside `<body>` (since `<PrismicPreview>` is just a script-like component).

Best practice would be to put it inside `<body>`. The current placement works in practice but is technically invalid HTML.

## 3. `page.tsx` — already covered in parent guide

The home page. Server component that:
1. Creates a Prismic client.
2. Fetches the "home" page document.
3. Passes its slices to `<SliceZone>` for rendering.

```tsx
export default async function Index() {
  const client = createClient();
  const home = await client.getByUID("page", "home");
  return <SliceZone slices={home.data.slices} components={components} />;
}
```

### `async` server component

Top-level `await` works in async server components — Next.js handles the Promise. The component is "awaitable" — the framework waits for the Promise to resolve before rendering.

### `getByUID("page", "home")`

Prismic's API: fetch a document of type `"page"` with UID (unique identifier) `"home"`. UIDs are slugs editors set in the Prismic dashboard.

## 4. `[uid]/` — dynamic route for Prismic UIDs

The `[uid]` folder means **any path segment matches**. Inside, `page.tsx` receives a `params` prop with the captured uid:

```tsx
type Params = { params: { uid: string } };

export default async function Page({ params }: Params) {
  const client = createClient();
  const page = await client.getByUID("page", params.uid);
  return <SliceZone slices={page.data.slices} components={components} />;
}
```

So `/about` → `params.uid = "about"` → fetches Prismic doc with UID "about".

If the page doesn't exist, Prismic throws → Next.js shows a 404.

## 5. `api/` — API routes

In App Router, an API route is a folder with `route.ts`:

```
app/api/preview/route.ts → handler for GET/POST /api/preview
```

```ts
// route.ts
import { NextResponse } from "next/server";

export async function GET(request: Request) {
  return NextResponse.json({ hello: "world" });
}

export async function POST(request: Request) {
  const body = await request.json();
  return NextResponse.json({ received: body });
}
```

Common API routes in this project: Prismic preview/exit-preview/revalidate endpoints (auto-generated by Prismic Next.js plugin).

### Difference from Pages Router (old Next.js)

| Pages Router | App Router |
| --- | --- |
| `pages/index.js` | `app/page.tsx` |
| `pages/about.js` | `app/about/page.tsx` |
| `pages/api/foo.js` | `app/api/foo/route.ts` |
| `pages/_app.js` (wraps all) | `app/layout.tsx` (wraps all) |
| `getServerSideProps` | `async function Page()` |
| All components client | Default to server, opt into client |

### Most common interview questions about App Router

1. **"What's a server component?"** — Component that runs ONLY on the server, sends HTML, can't have state/effects.
2. **"When do I use `"use client"`?"** — Whenever you need state, effects, event handlers, or browser APIs.
3. **"How do you fetch data in App Router?"** — Make the component `async`, `await` your data inside it.
4. **"What is `layout.tsx`?"** — A wrapper that persists across child routes; child routes render inside `{children}`.
5. **"How do I make a dynamic route?"** — Folder named `[paramName]`, access via `params.paramName`.
